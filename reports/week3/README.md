## 13. PBI and workflow
**PBI types**:
- User Story - description of the feature from the point of the customer
- Bug report - a notification and description of the bug in the work of the system
- Technical - something directly related to implementing functionality of the User Story
- Testing - request to test implemented functionality
- Documentation - issues related to documenting
- Research - issues related to researching some question needed for project implementation

**PBI priorities**:
- Must - PBI just has to be implemented in the product
- Should - The product will probably work without it, but it will still miss important part of functionality
- Could - A nice feature to implement if time allows it, but is not mandatory
- Won't - The feature should not be implemented

**PBI statuses**:
- To Do - the PBI remains in the Product Backlog and is not currently ready to start
- Ready - the PBI is selected for the current Sprint, assigned, estimated, has the required description and acceptance criteria, and can be started without major unanswered questions
- In Progress - work has started on the PBI
- Review - the current implementation is ready for review, and the issue-linked PR/MR is open or the review is actively happening
- Done - for a supporting or implementation PBI, the issue acceptance criteria are satisfied, the team Definition of Done is satisfied, the issue-linked PR/MR is merged into the protected default branch, and the PBI is complete for the Sprint; for a user-story issue, the story acceptance criteria are satisfied, the team Definition of Done is satisfied, and all linked supporting PBIs required to satisfy the story's acceptance criteria are reviewed, merged, verified, and marked Done

### Sprint Milestone Usage

Sprint milestone is used as the container for Sprint Backlog items. 
Every PBI selected for the current Sprint is assigned to the corresponding Sprint milestone. 
The milestone name contains the Sprint Goal, the description has Sprint start date, and Sprint end date. 

## 14. Roadmap

## Roadmap Summary

The current Sprint focused on delivering MVP v1 of the compliance-checking platform. The implemented scope included the website compliance check workflow and website content extraction, FL-152 violation detection, user account creation, and the main web interface.

PDF report generatio, was not completed during Sprint 1 and has been moved to Sprint 2. The next Sprint will complete this feature.

For the complete roadmap and planned future releases, see [docs/roadmap.md](https://github.com/TemporaryOrganization1/PDn-control/blob/main/docs/roadmap.md).
