# Week 5 Retrospective

## What Went Well

- The team delivered `MVP v2` with email verification and frontend changes.
- Architecture documentation, ADRs, quality requirements, testing documentation, and Definition of Done were connected into a more maintainable evidence set.
- The hosted documentation site made maintained docs easier to browse.
- Sprint Review produced concrete customer feedback for the next iteration.

## What Did Not Go Well

- The frontend redesign still did not fully satisfy the customer’s expectations for a polished SaaS product.
- Some report artifacts were created late and needed cleanup to become a coherent public submission index.
- Some evidence was scattered across GitHub, screenshots, transcripts, and Markdown files instead of being collected earlier during the Sprint.

## What We Learned

The team learned that customer-visible design quality matters as much as implemented functionality for product trust. We also learned that architecture and process documentation are easier to maintain when updated together with implementation work, not only at the end of the assignment.

## Concrete Process Change For Next Sprint

For the next Sprint, each PBI should include its expected public evidence before implementation starts: issue link, reviewer, test/CI evidence, screenshot or demo evidence if relevant, and documentation updates. This should reduce end-of-Sprint report cleanup and make review easier.
